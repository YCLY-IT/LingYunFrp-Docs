# API 概览

这一页讲调用 LingYunFrp 接口前要先知道的几件事。具体能用哪些接口，看[接口列表](/develop/endpoints)，也可查看APIFox中的的[接口列表](https://pcbbbrxrvv.apifox.cn)。

## 接口根地址

所有接口都挂在一个根地址下面。根地址由 `openapi.json` 的 `servers` 字段决定，在[接口列表](/develop/endpoints)页顶部可以直接看到并切换。

下面用 `<根地址>` 代替它，拼出完整的请求地址：

```
<根地址>/user/info
```

## 鉴权

需要登录的接口，必须在请求里带上凭证。用哪种凭证、放在哪个位置，以各个接口在规范里声明的 `security` 为准 —— 接口列表页会把它渲染出来，照着填就行。

| 方式 | 怎么传 |
| --- | --- |
| Bearer Token | 请求头 `Authorization: Bearer <token>` |

::: warning Token 就是密码
Token 能操作你名下的隧道和其他账户上的信息，别提交到仓库、别发在群里、别分享。怀疑泄露了就在面板上重置。
:::

::: tip 别和 frpc 的 Token 搞混
面板里那个 16 位的 Token 是 frpc 连节点用的，跟调用本 API 的凭证不是同一个东西，配置 frpc 时看[配置参考](/docs/configuration)。
:::

## 请求与响应

- 请求和响应体都是 JSON，请求时带上 `Content-Type: application/json`
- 带 body 的请求（`POST` / `PUT` / `PATCH`）用 JSON 编码，不要用表单
- 路径参数和查询参数的类型、是否必填，以接口列表页的参数表为准
- 时间统一用 ISO 8601 字符串；流量单位 MB，带宽单位 Mbps

## 错误处理

HTTP 状态码表示请求本身的结果，业务上的成败要看响应体里的业务码。

| HTTP 状态码 | 含义 | 该怎么做 |
| --- | --- | --- |
| `200` | 请求成功 | 看响应体里的业务码判断业务是否成功 |
| `400` | 参数有问题 | 对照参数表检查必填项和类型 |
| `401` | 没带凭证或凭证失效 | 检查 Token，必要时重新获取 |
| `403` | 凭证有效但权限不够 | 通常是用户组限制，换接口或升级用户组 |
| `404` | 接口不存在或资源不属于你 | 检查路径和 ID |
| `429` | 触发限频 | 放慢频率，稍后重试 |
| `5xx` | 服务端异常 | 重试，持续出现就反馈 |

::: info 业务状态码
业务状态码表还没录入规范。补齐后这一节会替换成完整表格，也可以在 `openapi.json` 的响应示例里直接查看。
:::

## 限频

接口有频率限制，超限会返回 `429`。建议：

- 别高频轮询，拉取类接口几秒一次就够了
- 收到 `429` 就退避重试，别立刻重发
- 批量操作尽量合并成一次请求

::: info 具体阈值
限频阈值还没录入规范，补齐后会写在这里。
:::
