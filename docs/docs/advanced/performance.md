# 性能调优

frp 的默认参数已经是官方调过的通用值，**速度和延迟都满意时，不建议改任何东西**。本页逐个说明可调参数的作用、代价，以及到底有没有必要开。字段位置等基础说明见[配置文件说明](../parameters/config-file)。

## 先认清瓶颈在哪

任何参数都无法突破物理上限。一条隧道的速度受限于四段中**最小**的一段：

```mermaid
flowchart LR
    A["访问者<br/>下行带宽"] --> B["节点带宽<br/>（套餐/节点规格）"]
    B --> C["你本机到节点<br/>的上行带宽与线路质量"]
    C --> D["本地服务<br/>处理速度"]
    style A fill:#e3f2fd
    style B fill:#fff3e0
    style C fill:#fff3e0
    style D fill:#e8f5e9
```

- 家庭宽带的**上行带宽**通常远小于下行（如下行 500Mbps、上行仅 30~50Mbps），穿透速度的天花板往往是它；
- 节点带宽、晚高峰拥塞见[节点线路选型](../parameters/node-select)；
- 参数调优只能减少额外开销，不能让 30Mbps 的上行跑出 100Mbps。

::: warning ⚠️ 调优的正确姿势
一次只改一个参数，改完用同一个测速方式对比（如下载同一个文件、连续 ping 看延迟/抖动）。一次改多个，出了问题无法判断是哪一项引起的。
:::

## 加密与压缩作用在哪一段

先明确范围，避免误解：

```mermaid
flowchart LR
    V["访问者"] -->|"① 这一段不受 useEncryption/useCompression 控制"| S["节点 frps"]
    S -->|"② 这一段才受控<br/>useEncryption / useCompression"| C["你的 frpc"]
    C -->|"③ 本机访问本地服务<br/>（局域网内）"| L["本地服务"]
```

也就是说：

- 开启后只改变 **节点 ↔ frpc** 这一段；
- 访问者 ↔ 节点之间是否是 HTTPS，取决于你有没有配置证书，与它无关（见 [SSL 证书](../scenarios/website-deploy/ssl-cert)）。

## 参数逐项说明

### transport.useEncryption（传输加密）

```toml
[[proxies]]
name = "web"
type = "tcp"
localPort = 80
[proxies.transport]
useEncryption = true
```

- **作用**：加密节点与 frpc 之间传输的数据，链路上的中间设备无法直接看到内容；
- **代价**：两端加解密占用少量 CPU。现代 x86 电脑、手机级 ARM 上基本感知不到；老旧路由器（MIPS 小主频设备）跑满带宽时可能成为瓶颈；
- **有没有必要**：
  - 传输敏感内容（远程管理、数据库、未加密的内网后台）→ **建议开**；
  - 普通网页、游戏联机 → 开不开影响不大，图省心可以统一开；
  - 它**不能替代** HTTPS：浏览器地址栏不会因此变成小锁，访问者到节点这一段仍然是明文。

### transport.useCompression（传输压缩）

```toml
[proxies.transport]
useCompression = true
```

- **作用**：压缩节点与 frpc 之间的数据，文本类内容（网页、日志、API、远程终端）体积可明显变小，省流量、弱网下可能更快；
- **代价**：两端压缩/解压占用 CPU，且对**已经压缩过的数据不仅无效，还可能略微变大、增加延迟**；
- **有没有必要**：

| 流量类型 | 压缩效果 |
| --- | --- |
| 网页 HTML/CSS/JS、日志、终端、纯文本 API | 有效，可开 |
| 游戏联机数据、视频/语音、图片视频文件下载、HTTPS 流量 | 基本无效，不建议开（纯耗 CPU） |

不确定时就不开——压缩带来的收益在大多数宽带下并不明显。

### transport.bandwidthLimit（带宽限制）

```toml
[proxies.transport]
bandwidthLimit = "2MB"
# bandwidthLimitMode = "client"   # client=在 frpc 侧限速（默认）；server=在节点侧限速
```

- **作用**：给单条隧道设置带宽上限，避免一条隧道占满全部上行，影响其他隧道或家里正常上网；
- **单位**：MB/s（字节），与面板常见的 Mbps（比特）换算：**1 MB/s = 8 Mbps**，速查表见[配置文件说明 · 带宽单位换算](../parameters/config-file#带宽单位换算)；
- **有没有必要**：**绝大多数用户不需要**。它只能「限速」不能「提速」；只有多隧道共用一条小水管、需要给重要隧道保底时才用得上。面板侧通常已按套餐有带宽上限，以面板说明为准。

### transport.tcpMux（多路复用，默认开启）

```toml
transport.tcpMux = true   # 默认即 true，无需手动填写
```

- **作用**：让所有隧道的流量复用 frpc 与节点之间的同一条 TCP 连接，减少反复建连的握手开销；
- **有没有必要**：**保持默认即可，不要关**。只有在排查极少数兼容性问题、官方支持明确要求时才关闭。

### transport.poolCount（预连接池，默认 0）

```toml
transport.poolCount = 2
```

- **作用**：提前建好 2 条（可自定义数量）到节点的工作连接放在「池子」里，新用户请求到来时直接取用，省去临时建连的几十~几百毫秒；
- **代价**：即使没有流量也会长期占用连接和少量两端资源；
- **有没有必要**：
  - **高频短连接**场景（有人频繁访问的网站、API 服务）：可试 `2` 或 `5`，首次响应可能更快；
  - **长连接**场景（游戏、SSH、远程桌面）：没有意义，保持 `0`；
  - 收益是「首包延迟」级别，不影响大文件传输的峰值速度。

### transport.protocol（传输协议，默认 tcp）

可选 `tcp`（默认）、`kcp`、`quic`、`websocket`、`wss`。

- **作用**：改变 frpc 与节点之间的底层传输协议。KCP / QUIC 基于 UDP，在**丢包率高**的网络中通过更快的重传策略降低卡顿，代价是更耗流量、对节点要求更高；`websocket/wss` 主要用于必须走 HTTP 代理才能出网的受限网络；
- **前提（重要）**：KCP / QUIC / wss **需要节点侧开放对应端口和协议支持**。LingYunFrp 各节点是否支持以面板节点说明/官方公告为准，**没有写明支持就不要开**，否则 frpc 无法登录节点；
- **有没有必要**：
  - 默认 TCP 正常使用 → 不需要动；
  - 游戏联机在晚高峰频繁卡顿、且确认节点支持 KCP/QUIC → 可以对比测试；
  - 公司网络只放行 HTTP/HTTPS → 才考虑 websocket/wss。

心跳、重连间隔等稳定性参数（`heartbeatInterval`、`heartbeatTimeout` 等）的说明见[配置文件说明](../parameters/config-file)，默认值适用于绝大多数网络，不要随意调小。

## 必要性速查表

| 参数 | 默认 | 什么时候改 | 不满足条件时 |
| --- | --- | --- | --- |
| `useEncryption` | 关 | 传输敏感内容，或希望全链路（frpc↔frps）加密 | 保持默认 |
| `useCompression` | 关 | 纯文本类流量、带宽紧张 | 已压缩流量保持默认 |
| `bandwidthLimit` | 不限 | 多隧道争抢上行，需要主动限速 | 保持默认（面板已有套餐上限） |
| `tcpMux` | 开 | 不要改 | —— |
| `poolCount` | 0 | 高频短连接的网站/API | 长连接场景保持 0 |
| `protocol` | tcp | 高丢包网络（需节点支持 KCP/QUIC）/ 受限网络（ws/wss） | 保持 tcp |

## 什么时候该怀疑「不是参数问题」

- 所有人都慢、晚高峰必卡 → 节点拥塞，换节点比调参数有效，见[节点线路选型](../parameters/node-select)；
- 速度始终卡在某个整数（如 3MB/s 左右不动）→ 先算你的上行带宽（约 24Mbps），大概率是物理上限；
- 时通时断、日志有重连 → 是稳定性问题，按[故障排查](../parameters/troubleshooting)处理，调性能参数无效。
