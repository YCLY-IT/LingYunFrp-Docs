# 游戏开服联机

在本地（家里电脑、小主机或 NAS）运行游戏服务端，通过 LingYunFrp 让好友从公网连入。

## 游戏流量怎么走

```mermaid
flowchart LR
    F["好友的游戏客户端"] -->|"连接 节点IP:远程端口"| N["LingYunFrp 节点"]
    N -->|"隧道回流"| C["你网络里的 frpc"]
    C -->|"127.0.0.1:游戏端口"| S["游戏服务端"]
```

好友连的不是你的家庭 IP，而是**节点 IP + 面板分配的远程端口**，所以：

- 不需要有公网 IP，也不需要动家里路由器的端口转发；
- 远程端口由面板分配，frpc 配置必须与面板一致。

## tcp 还是 udp？

游戏协议不同，隧道类型必须对应，错了会表现为「能看到服务器但进不去」或一直超时：

| 协议 | 典型游戏 |
| --- | --- |
| **TCP** | Minecraft Java 版、泰拉瑞亚、7 日杀 |
| **UDP** | Minecraft 基岩版、CS2/CS:GO、幻兽帕鲁、方舟、Valheim、Rust、异星工厂等大多数实时游戏 |

少数游戏同时使用两种协议（例如既要游戏连接又要 RCON 远程管理），就**分别创建 tcp 和 udp 两条隧道、映射各自端口**；TCP 与 UDP 端口在节点上互不冲突，可使用相同的远程端口号。

## 公开联机还是私密联机？

| 方式 | 谁能连 | 适合 |
| --- | --- | --- |
| `tcp` / `udp` 普通隧道 | 任何知道 `节点IP:端口` 的人 | 朋友间小范围公开、社区服 |
| `stcp` 私密隧道 | 只有持有相同 `secretKey` 且也运行 frpc 的好友 | 不想被扫描、被陌生人蹭服 |

stcp 的代价是每位好友都需要运行一个 frpc 作为访问者（visitor）。Minecraft 的完整双端配置示例见 [Minecraft 开服 · 私密联机](./mc#stcp-私密联机仅好友可连)。

## 开服前的通用检查清单

1. **本机能连**：先在运行服务端的机器上用游戏客户端连 `127.0.0.1:游戏端口`，本机不通，穿透一定不通；
2. **端口对上**：服务端配置文件里的监听端口 = 隧道的 `localPort`，注意有些游戏游戏端口和查询端口不是同一个；
3. **协议对上**：按上表选择 tcp/udp，不确定时查游戏官方 wiki；
4. **防火墙放行**：Windows 首次启动服务端会弹防火墙提示，勾选「专用网络」；Linux 上本机访问一般不受影响；
5. **内存够吗**：游戏服吃内存（MC 模组服建议 4GB 起步给服务端），边玩边开建议 16GB 总内存以上；
6. **上行带宽**：每位玩家大约需要几十~几百 kbps 上行，语音/模组下载另算；多人卡顿多半是上行瓶颈，见[性能调优](../../advanced/performance)。

## 个人电脑开服建议

- **临时开黑**：直接在 Windows/macOS 上跑服务端 + 图形客户端，玩完就关，最省心；
- **长期生存服**：找一台有线联网的旧台式机或 Linux 小主机常开，用 [Linux 可视化面板](./panels) 管理，手机网页就能重启服务器；
- macOS 用户注意：**不少 Steam 游戏的专用服务端只有 Windows/Linux 版本**（如 CS2、幻兽帕鲁），Mac 上请用 Linux 小主机/云主机，或在 Mac 上用容器/虚拟机运行 Linux 版服务端。

## 安全提醒

- 服务端后台（RCON、游戏控制台、面板管理页）不要通过公网 tcp 暴露，需要远程管理时用 stcp；
- 给服务端设置管理员密码 / OP 权限分级，面板开启白名单；
- 公开服建议开启正版验证（MC 的 `online-mode`）或反作弊插件。
